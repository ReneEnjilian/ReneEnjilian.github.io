Open source / Apache Software Foundation

Apache SystemDS.

Selected contributions to the compiler, runtime, and GPU backend.

CUDAJava / JNISparse matrices

Apache SystemDS is an open-source machine learning system covering the end-to-end data science lifecycle, from data preparation and model training to debugging and serving. It automatically compiles high-level programs into hybrid execution plans combining local, in-memory CPU operations and distributed computation on Apache Spark, with additional support for GPU acceleration and federated learning.

I am an Apache SystemDS committer. The contributions below grew out of my research work at BIFOLD / TU Berlin and span the compiler, runtime, GPU backend, and machine learning algorithms.

01

GPU backend modernization

I upgraded the GPU backend from CUDA 10.2 to CUDA 12.6, updating its integration with cuSPARSE, cuBLAS, and cuDNN 9. This involved replacing deprecated APIs and adapting sparse matrix operations to the requirements of the newer libraries, including CSR transposition and sorting on the GPU.

These changes keep the backend compatible with the updated NVIDIA software stack. I also extended the GPU test suite to check the affected execution paths and make future regressions easier to diagnose.

  • GPU backend upgrade #2271↗

02

Custom Java–CUDA bindings

I developed cuJava, a set of custom Java–CUDA bindings with matching C++/JNI implementations for the CUDA runtime, driver, cuBLAS, and cuSPARSE. The contribution includes native pointer handling and a CMake-based build that produces the corresponding shared libraries on Linux.

The bindings target the NVIDIA library calls used by SystemDS. Limiting this scope is intended to simplify maintenance and future CUDA upgrades, while giving the project direct control over its Java–CUDA integration.

  • cuJava bindings #2311↗

03

Sparse matrix representations

I implemented Compressed Sparse Column (CSC) and Modified Compressed Sparse Column (MCSC) blocks, adding column-oriented representations alongside SystemDS’s existing row-oriented formats. These structures provide a basis for exploring operations that benefit from column access; the contributions focused on the representations and their tests, with deeper runtime integration left for subsequent work.

I also introduced an iterator over non-empty row indices for DCSR, MCSR, CSR, and COO blocks. It lets an operation skip entirely empty rows and provides a building block for investigating the benefits of these formats on sparse workloads.

  • CSC block #2132↗
  • MCSC block #2040↗
  • Non-empty row iterator #2005↗

04

Scalable Linear Algebra Benchmark (SLAB)

I implemented SLAB workloads for SystemDS across matrix operators, pipelines and decompositions, and linear algebra-based machine learning algorithms. The benchmark varies matrix dimensions and sparsity, with workloads for local execution and Apache Spark.

This provides a structured way to examine how performance changes with data characteristics and workload complexity. Running the benchmarks also exposed an issue in transpose-self matrix multiplication. The experiments reported in the PR used a single machine, including the Spark runs.

  • SLAB benchmark #2055↗

05

Machine learning algorithms

I implemented AdamW and Scaled Gradient Descent (ScaledGD) in DML, extending the optimization algorithms available in SystemDS. Expressing these methods in the system’s high-level language makes them available to machine learning pipelines through its compiler and runtime.

I also contributed the DML implementation of ADASYN (Adaptive Synthetic Sampling), which generates synthetic minority-class samples for imbalanced binary classification datasets. Together, these contributions extend the available methods for model optimization and training-data preparation.

  • AdamW and ScaledGD #2206↗
  • ADASYN #2133↗

06

Compiler rewrites and validation

I added algebraic rewrites that simplify high-level expressions before execution. A matrix distributivity rewrite factors out a shared matrix multiplication for dense matrices when the required matrix properties are known and the estimated number of floating-point operations decreases. Additional rewrites simplify negated comparisons by replacing them with their equivalent comparison operators.

I also expanded tests for static and dynamic algebraic simplifications and matrix multiplication chain optimizations. The tests exposed pattern-matching issues, missing transpose handling, and optimization passes that were not connected to the rewriter. This work helps establish whether optimizations are both correct and actually applied.

  • Matrix distributivity #1986↗
  • Negated comparisons #1988↗
  • Rewrite validation #2109↗
